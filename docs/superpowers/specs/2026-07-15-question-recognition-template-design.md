# 题目识别与题目模板优化设计

## 目标

在 Word、PDF、PPT、JSON 和 CSV 导入流程中提高题目边界、题型、选项、答案与解析的识别准确率，同时坚持保守策略：证据不足时保留原文并给出诊断，不自动执行可能破坏题意的转换。

本次优化覆盖：

- 混乱排版、题号断行和选项跨段。
- 答案与解析混排、标签变体和独立答案区。
- 单选、多选、判断、填空、计算、论述、编程题的判定。
- 题型模板切换时的选项、答案、填空位和解析保留。
- 可解释的置信度、冲突原因和质量警告。

不在本次范围内：

- 使用外部大模型自动重写题目。
- OCR 图片文字识别。
- 自动修正题目知识内容或参考答案正确性。
- 多用户自定义识别规则编辑器。

## 设计原则

1. 原文优先：无法确认的文本留在题干或保留字段中。
2. 明确信号优先：章节标题和字段标签权重大于关键词猜测。
3. 可解释：每次推断记录证据、置信度和冲突。
4. 可逆：模板切换不得静默丢失原题数据。
5. 分层处理：结构恢复、分题、字段识别、题型推断彼此独立。
6. 兼容现有数据：数据库题型和导入 API 响应保持兼容。

## 识别流水线

### 1. 文本结构恢复

输入为文档解析后的段落序列。该层只恢复结构，不判断题型。

统一处理：

- 全角字母、数字和标点。
- 不同换行符、连续空白和不可见字符。
- PDF 页码、页眉、页脚和孤立装饰文本。
- PPT 文本框中的重复内容和异常二进制文本。
- Word 表格单元格与普通段落的顺序。

输出 `StructuredParagraph[]`：

```ts
interface StructuredParagraph {
  text: string
  sourceIndex: number
  sourceKind: "paragraph" | "table" | "slide" | "pdf-line"
  styleHints: {
    isRed?: boolean
    isBold?: boolean
    level?: number
  }
}
```

不得在此层删除无法确认的正文。

### 2. 题目边界识别

使用多个边界证据，而不是单一题号正则：

- 明确章节标题，如“单项选择题”“二、判断题”。
- 独立题号，如 `1.`、`1、`、`（1）`、`第1题`。
- 题号与题干同行。
- 上一道题已经出现完整选项和答案，后续出现新题号。
- 选项、答案、解析标签不得单独触发新题目。

每个候选题块输出边界置信度。低置信度边界与前一题合并，并增加 `uncertain_boundary` 警告，避免把一题拆成多题。

### 3. 字段识别

字段识别顺序固定为：解析、答案、选项、题干。先移除尾部明确字段，再处理选项，剩余内容作为题干。

#### 答案

允许的强信号：

- `答案`、`正确答案`、`参考答案`、`标准答案`、`Answer`、`Ans`。
- 独立答案区中的题号与答案映射。
- Word 红色文本，但仅在文本长度和题型格式符合时使用。

普通题干末尾的单个字母不再直接视为答案，除非同时满足：当前题为选择题、选项包含该字母、字母与题干之间存在明确分隔。

#### 解析

允许标签：`解析`、`答案解析`、`详解`、`解答`、`说明`、`分析`。解析可以跨多个段落，直到下一题边界。

答案内容中出现“因为”“所以”等词不能作为解析分隔信号。

#### 选项

支持：

- `A.`、`A、`、`A)`、`A）`、`（A）`、全角字母。
- 多个选项位于同一段落。
- 选项正文在下一段续写。
- 表格或多列文本被解析为连续段落。

只有检测到至少两个连续、不同的选项标号时才建立选项列表。单独出现 `A.` 时保留在题干，并产生 `uncertain_option` 警告。

### 4. 题型推断

题型通过证据评分确定：

| 证据 | 分值 |
|---|---:|
| 明确章节题型 | 100 |
| 题目自身题型标签 | 90 |
| 两个及以上选项 | 50 |
| 多个有效选项答案 | 多选 +35 |
| 单个有效选项答案 | 单选 +25 |
| 判断答案或判断占位 | 判断 +45 |
| 两个及以上填空标记 | 填空 +40 |
| 代码块或程序运行要求 | 编程 +35 |
| “计算、求解、证明”关键词 | 计算 +20 |
| “简述、分析、论述”关键词 | 论述 +15 |

判定规则：

- 章节题型存在时默认采用章节题型，除非出现不可兼容的强证据。
- 最高分与次高分差值不足 20 时，不自动改变章节题型或默认题型。
- 没有章节题型且证据不足时使用 `essay`，并产生 `uncertain_type`。
- 选择题存在多个答案字母时可判定为多选；没有答案时不能仅凭选项数量区分单选和多选。
- 判断题必须有判断答案、判断占位或明确章节信号之一。

输出：

```ts
interface TypeDecision {
  type: QuestionType
  confidence: number
  evidence: string[]
  alternatives: Array<{ type: QuestionType; score: number }>
}
```

## 诊断模型

每道识别结果增加可选诊断，不改变数据库字段：

```ts
interface RecognitionDiagnostic {
  confidence: number
  warnings: Array<{
    code:
      | "uncertain_boundary"
      | "uncertain_type"
      | "uncertain_option"
      | "answer_option_mismatch"
      | "blank_answer_mismatch"
      | "conflicting_signals"
    message: string
    sourceText?: string
  }>
  evidence: string[]
}
```

诊断随预览 API 返回，导入页面显示为质量提示。正式保存题目时不持久化诊断，避免数据库迁移。

## 模板模型

### 可逆编辑状态

`EditableQuestion` 增加可选 `preserved` 字段：

```ts
interface PreservedTemplateData {
  sourceType: QuestionType
  options?: string[]
  answer?: string
  blanks?: BlankSlot[]
}

interface EditableQuestion {
  type: QuestionType
  stem: string
  options?: string[]
  blanks?: BlankSlot[]
  answer?: string
  explanation?: string
  preserved?: PreservedTemplateData
}
```

模板切换规则：

- 选择题切换为非选择题：选项存入 `preserved.options`，不写入正式题目选项字段。
- 填空题切换为其他题型：填空位和分项答案存入 `preserved.blanks`。
- 切回原题型时优先恢复 preserved 数据。
- 目标模板能够表达当前答案时保留；不能表达时保留到 `preserved.answer` 并清空目标模板答案，同时产生模板警告。
- 用户在目标模板中主动修改对应字段后，以用户输入为准，不再覆盖。

### 模板约束

- 单选题：至少两个非空选项，答案最多一个有效选项字母。
- 多选题：至少两个非空选项，答案可以包含多个有效字母。
- 判断题：答案仅为 `√`、`×` 或空值。
- 填空题：题干中的编号填空位与 `blanks` 一一对应；答案数量不一致时保留全部答案并警告。
- 计算、论述、编程题：不保存选项；答案和解析保持原始换行。

### 填空模板

识别以下占位符：

- `____`、连续三个及以上下划线。
- `（ ）`、`( )`、`【 】`、`[ ]`。
- 已编号的 `____{1}`。

已有编号必须保留并重新建立有序 blanks，不得把 `____{1}` 再次替换成新的编号。未编号占位符按出现顺序编号。切换并恢复模板后编号保持稳定。

## 模块边界

计划拆分为：

- `parser/structure-normalizer.ts`：文档段落结构恢复。
- `parser/question-segmenter.ts`：题目边界识别。
- `parser/field-extractor.ts`：选项、答案、解析提取。
- `parser/type-classifier.ts`：证据评分和题型决定。
- `parser/question-extractor.ts`：编排各层并兼容现有导出函数。
- `parser/question-templates.ts`：模板转换和 preserved 数据。
- `parser/question-normalizer.ts`：格式标准化与质量校验。

各模块使用纯函数和结构化输入输出，文档格式解析器只负责生成段落序列。

## 错误处理

- 无法提取任何题目时保持现有 400 错误。
- 部分题目低置信度时仍返回预览结果，并附带警告。
- 不支持格式、损坏文档和解析库异常继续由 API 错误层处理。
- 规则内部异常不得吞掉整批结果；定位到单题时将原始题块保留为论述题并附加诊断。

## 测试策略

### 单元测试

- 结构规范化：全角标点、孤立题号、页码、重复 PPT 文本。
- 分题：题号断行、题号同行、答案区、解析跨段。
- 字段：同行选项、断行选项、表格选项、标签变体和引号。
- 分类：章节与答案冲突、无答案选择题、判断占位、填空标记、代码题。
- 模板：七种题型互转、切回恢复、填空编号稳定和无损往返。

### 回归样例

每个失败样例应保存为最小文本或 HTML fixture，不提交含个人信息的原始试卷。至少覆盖：

- Word 红色答案。
- PDF 页眉页脚和跨行选项。
- PPT 同页多个文本框与重复文本。
- 选择题答案位于题干末尾。
- 解析中包含选项字母或“答案”字样。
- 填空答案数量与空位不一致。

### 验收指标

- 现有解析器与模板测试全部通过。
- 新增不少于 25 个针对混乱排版和模板互转的断言。
- 保守样例中不得静默丢失原文、选项、答案或填空位。
- `question-extractor.ts` 仅保留编排和格式适配职责，核心识别逻辑进入独立模块。
- 导入预览能够显示低置信度和冲突警告。
- ESLint、TypeScript、完整测试和生产构建通过。

## 兼容与迁移

- `ExtractedQuestion` 的现有字段保持不变，只增加可选诊断。
- `EditableQuestion.preserved` 为可选字段，旧客户端和旧预览数据仍可使用。
- 数据库 schema 不变。
- 现有 API 路径、请求格式和正式导入格式不变。
